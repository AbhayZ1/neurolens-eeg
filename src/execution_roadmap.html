NeuroLens · Seizure Prediction Pipeline

Execution Roadmap

From raw CHB-MIT EDF files to paper-ready LaTeX tables and figures — what to run, in what order, and what to expect at each stage.

Before you start This roadmap assumes real CHB-MIT data and multi-hour runtime. Every script here has been mechanically verified end-to-end — shapes, gradients, subprocess wiring, JSON schema, plotting — against synthetic stand-in data, but never against the real dataset, which isn't present in this environment. Treat a first real run's model-quality numbers (sensitivity, AUC, etc.) as a first read, not a final result.

1 Sanity checks first

Minutes, not hours — catch configuration problems before committing GPU time.

  --synthetic_duration_min 2 --synthetic_transition_start_min 1 --synthetic_n_trials 1 \

2 Full run

3
Launch the real experiment 
python run_experiments.py \
  --data_dir /path/to/chb-mit-scalp-eeg-database-1.0.0 \
  --output_dir runs/exp1 \
  --patients chb01 chb02 chb03 \

Produces results_table.tex, faithfulness_table.tex, tas_vs_time_to_seizure.png. Needs no GPU, torch, or mne — it can run on a laptop with just that one JSON file copied over.

4 GPU memory considerations

  • The model itself is small — ~0.7M params at the default architecture (d_model=64). Not the memory bottleneck.
  • MC-Dropout inference batches the replica dimension: get_mc_prediction(x, num_samples=30) runs one forward pass on a batch replicated 30×. At batch_size=32, that's an effective batch of 960 — if evaluation OOMs, lower --mc_samples before --batch_size.
  • Counterfactual PGD averages mc_samples_grad (default 5) differentiable forward passes per iteration, for up to 100 iterations, per faithfulness sample — the second-heaviest step in evaluation after MC inference.
  • FAISS index build re-embeds the entire training set once at the end of each fold (a full extra pass) — budget for this in your Stage 1 time estimate, not just epochs × epoch time.
  • Starting point for an 8–12 GB GPU: default architecture, --batch_size 32, --mc_samples 30. Scale down batch_size first if you hit OOM.

5 Troubleshooting

  • "No trajectories of length k could be built" during FAISS export — that fold's training set has no contiguous run ≥ --trajectory_k (default 12) windows long. Try a smaller --trajectory_k, or check the patient has enough seizures for LOSO to leave meaningful preictal data behind.
  • Fold skipped, "produced an empty split" — that LOSO fold's train/val/test partition came back empty (very sparse recording relative to the interictal/preictal window rules). Check experiment_run.log for which fold.
  • "validation set has a single class; skipping temperature scaling" — expected and harmless on small/early folds; temperature defaults to 1.0 (no calibration correction) for that fold.
  • bifurcation: null or a note about "no historical preictal trajectories" — that fold's training data had no preictal FAISS class (common for patients with very few seizures under LOSO). Not a crash; BPE just isn't computable for that fold.
  • CIs in statistical_summary.json look absurdly wide — check n for that metric. At small fold counts the Student's-t critical value is large; this is mathematically correct, not a bug, and tightens as more folds succeed.
  • Resuming after a crash — pass --skip_training to re-run Stage 2/3 against an existing --output_dir/checkpoints without repeating Stage 1.
